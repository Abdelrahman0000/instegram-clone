# Instagram Clone

Built by Abdelrahman Samer Kalefa.

Independent Instagram-style portfolio app. Not affiliated with Instagram or Meta.

## Stack

React 19, Vite 6, Supabase Auth, Postgres, Storage and Realtime. A publishable client key is intentionally included in `src/supabase-config.json`. No database password, service-role key, Vercel token or other privileged credential belongs in the client or repository.

## Implemented

- Email/password signup and login forms, independent app credentials, anonymous guest accounts, logout and account settings.
- Public profiles, editable username/name/bio/website/avatar.
- Separate one-way follow/unfollow and reciprocal friend request, accept, decline, cancel, remove and private friend lists.
- Persistent photo/video posts, caption/location edits, deletion, likes, comments, saves, post sharing in private chat and public post links.
- Explore, search, profile grids, video Reels, expiring 24-hour stories and notifications.
- Private account-to-account text, image and video messages, private attachments, read receipts, unsend and earlier-message loading.
- Responsive desktop/phone layouts and light/dark appearance.
- Six labeled fictional demo accounts, 12 credited stock photographs, two animated-stock demo reels and four initially seeded 24-hour stories. Demo accounts have no working sign-in and do not send automatic replies.

## Honest demo limits

- Not full feature parity with the Instagram service. No Instagram account access, official social login, calls, live broadcasts, music library, paid promotion, facial filters or private-profile mode.
- JPG, PNG, WebP, GIF, MP4 and WebM only, maximum 20 MB per file. Video codec support depends on the browser. One image or video per post.
- Public profiles, posts and stories. Chat and saved-post access is enforced through database and storage policies, not merely hidden in the interface. Chat is not end-to-end encrypted.
- Email ownership confirmation is intentionally off for this portfolio demo. Use a separate password and do not share sensitive information. No password-reset email flow is advertised.
- Guest accounts persist in the current browser. They do not provide a reusable email login on other devices.
- The initial feed fetches the latest 100 posts, and notifications/inbox summaries the latest 300 rows. Open conversations load earlier messages in batches of 50. This is a small portfolio demo, not a production-scale social network.
- Supabase Free limits and inactive-project pausing still apply. No paid upgrade was made.

## Run

```
npm ci
npm run dev
npm run build
```

`vercel.json` contains SPA routing and security headers. `public/seed/credits.json` records each stock photograph's source and author. License: https://unsplash.com/license . The site includes the same credits in About.

## Database

The dedicated project is already provisioned. Do not blindly rerun `schema.sql` against it. `supabase/schema.sql` is the initial schema and policies for a new isolated project. `supabase/seed.sql` installs the six fictional demo personas and their posts after that schema. No existing unrelated Supabase app was changed.

Rows have RLS, client writes are restricted to their owner, notifications are generated by database triggers, privileged profile flags cannot be changed by clients, and friend actions run through narrowly scoped functions. Public post media and private chat attachments are separate buckets. All functions with elevated rights set an empty search path and have explicit execution grants.

## Verification

`npm run test:integration` tests real Supabase persistence and access control with three temporary accounts, then removes their media and accounts. It creates database data, so only run against the intended test/demo project.

`npm run test:ui` starts the local site, runs real browser interactions against Supabase and removes its temporary account afterward. Browser executable currently defaults to `/usr/bin/google-chrome` in the test script.

Recorded checks cover media persistence, friends, follows, likes, saves, comments, stories, private chat and attachments, read receipts, notifications, ownership denials, account-private rows and cascading deletion. Actual desktop and phone screenshots were inspected. A final hosted deployment check and the remaining email/password UI check must be completed before release is reported as done.
